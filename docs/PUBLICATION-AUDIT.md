# Проверка перед публикацией

Дата проверки: 13 октября 2026 года. Это воспроизводимая проверка исходников, зависимостей и публикуемых файлов; независимый pentest не проводился.

## Секреты и данные

Использован [Gitleaks 8.30.1](https://github.com/gitleaks/gitleaks/releases/tag/v8.30.1) со стандартными правилами и дополнительным правилом для rescue-ключей Custodian. Linux x64 архив проверяется по закреплённому SHA-256:

```text
551f6fc83ea457d62a0d98237cbad105af8d557003051f41f3e7ca7b3f2470eb
```

Проверены:

- Рабочие исходники, документация, конфигурация, логотип и скриншоты: tracked и untracked файлы, не исключённые `.gitignore`.
- Весь доступный граф Git через `--all --full-history -m`, включая merge patches и локальные refs.
- Имена файлов в Git и архивах: `.env`, приватные ключи и файлы credentials отсутствуют. Публикуется только шаблон `.env.example`. В release архивах нет `.git` и `node_modules`.
- Четыре PNG 2560×1440: синтетические записи, адреса `example.com` и `192.0.2.10`, скрытые пароли и TOTP. У скриншотов отсутствуют текстовые и EXIF metadata. У логотипа сохранены C2PA данные происхождения, без prompt и локальных путей.

Подтверждённых секретов в проверенном материале не найдено. Единственное исключение Gitleaks ограничено точным общедоступным тестовым вектором RFC 6238 в `tests/crypto.test.ts` и `tests/dev-server.ts`. Оно не исключает остальные значения, файлы тестов или историю целиком. Дополнительная проверка подтверждает, что тот же вектор в другом файле вызывает ошибку сканирования.

Локальный `.env` не открывается. Проверяется только исключение из Git и отсутствие в его истории. Исключённые локальные файлы, production база, реальные пользовательские данные и секреты окружения CI не публикуются и не входят в скан исходников.

## Повторная проверка

```bash
npm ci
npm run secrets:check
npm run secrets:check -- --artifacts-only --path dist/release
```

Основная команда проверяет рабочие файлы и все локальные Git refs. `--path` можно повторить, чтобы добавить явно выбранные каталоги или файлы. Для полного history scan CI должен получать историю Git без shallow checkout.

На Linux x64 скрипт скачивает закреплённый официальный Gitleaks в закрытый временный каталог, проверяет SHA-256 и удаляет его по завершении. На другой платформе установите эту же версию и задайте `GITLEAKS_BINARY=/path/to/gitleaks`. Проверка не обращается к сервисам для верификации найденных токенов.

Архивы сканируются с раскрытием до трёх уровней, encoded значения - до пяти уровней. До сканирования `.tar.gz` проверяются имена entries: абсолютные пути, `..`, `.git`, `node_modules` и запрещённые файлы останавливают публикацию. Для отдельной проверки можно передать уже извлечённые source/runtime каталоги.

Вывод содержит только rule, filename, line и commit. Значения, совпавшие строки, scanner stdout/stderr и raw reports не выводятся и не публикуются. Ошибка установки или выполнения сканера также останавливает проверку. Ignore-файл, baseline и комментарии `gitleaks:allow` не подавляют находки.

## Зависимости и границы проверки

`npm audit` полного дерева зависимостей завершился без известных уязвимостей. В проверенном production lockfile внешние пакеты заявляют MIT, ISC, BSD-3-Clause, Apache-2.0, 0BSD, BlueOak-1.0.0 или OFL-1.1; GPL/AGPL пакетов нет. Лицензии и copyright сторонних пакетов сохраняются, шрифты не перелицензируются. CycloneDX SBOM каждого релиза фиксирует версии зависимостей.

Вручную проверены существующие границы backend: Origin/CSRF для мутаций, HttpOnly session cookies, одноразовые приглашения и WebAuthn challenges, owner/admin права, optimistic concurrency при сохранении/ротации, обязательный user verification, отсутствие PRF output в серверном payload, CSP и запрет API caching. Модель E2EE и восстановления остаётся описанной в [SECURITY.md](SECURITY.md).

Автоматический скан не доказывает отсутствие всех видов секретов. Он не читает текст внутри PNG и не проверяет, что произвольное значение больше не действует. Скриншоты проверяются отдельно по демонстрационному источнику и визуально. Публичный snapshot и окончательные release архивы проходят повторную проверку после сборки; результаты предыдущих файлов не заменяют этот этап.

Публичный репозиторий начинается с отдельного снимка кода. Прежние Git refs, локальные заметки по продукту и дизайн-ревью в него не переносятся. Для контейнера используется новое имя `ghcr.io/trillvertual/custodian-app`; прежние версии образа не публикуются вместе с ним.
