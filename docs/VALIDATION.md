# Проверки Custodian 0.4.0

Дата: 14 октября 2026 года. Node.js 22.23.3. Для всех тестов используются изолированные базы и синтетические данные.

## Проверено локально

| Проверка                                   | Результат                                                                                   |
| ------------------------------------------ | ------------------------------------------------------------------------------------------- |
| `npm run typecheck`                        | Успешно: frontend, backend, core, rescue, scripts и тесты                                   |
| `npm test`                                 | 82 теста в 13 файлах прошли                                                                 |
| `npm run build`                            | Успешно: frontend и оба Node.js entrypoint                                                  |
| `npm run release:check`                    | Версии и контракт релиза согласованы                                                        |
| `npm audit`                                | 0 известных уязвимостей в полном дереве                                                     |
| `npm run secrets:check` с build-каталогами | 0 находок в рабочих файлах, доступных Git refs и собранных web/server/rescue файлах         |
| Полный Playwright suite в Chromium 156     | 28 desktop/mobile сценариев; 56 проверок axe в обеих темах без нарушений проверенных правил |

Для v0.4.0 добавлены реальные encrypted batch CRUD, конкурентные повторы и полный rollback при конфликте, личное шифрование черновиков, ревизии и конфликты вкладок, аварийный буфер и восстановление сразу после перезагрузки, PNG QR, вставка, синтетическая камера и остановка поздно разрешённого MediaStream. Потеря ответа после успешного сохранения повторяет тот же ciphertext и оставляет одну запись. Новые suite используют отдельные синтетические API, сохраняя production лимит входа.

Прежние сценарии проверяют быстрые действия и clipboard, горячие клавиши, сохранение только ID недавних записей, замену шаблона с подтверждением и создание отдельной зашифрованной записи без изменения оригинала. Unit-тесты проверяют очистку всех значений при копировании структуры, изоляцию истории по пользователям и отмену отложенного копирования после закрытия, блокировки, смены ключей или запроса.

Функциональные browser-сценарии проверяют зашифрованные CRUD/history/trash, clipboard, ручную блокировку, custom controls, клавиатуру, адаптивность и непрерывность диалогов. Финальные сценарии доступности также проверяют reduced motion, переполнение страницы и получение Brotli ресурсов.

React/Fastify/libsodium/PGlite тесты проверяют регистрацию владельца, обязательное сохранение rescue-ключа, Origin/CSRF, права owner/admin, одноразовые приглашения, optimistic concurrency, смену пароля без изменения ciphertext, отзыв и ротацию ключей. Rescue-проверки включают неверный ключ, rollback, восстановление владельца, отзыв прежних методов входа, права plaintext-файла 0600 и отказ перезаписывать существующий файл.

WebAuthn assertion подписывается синтетическим P-256 ключом и проверяется настоящим SimpleWebAuthn verifier; отсутствие user verification отклоняется. PRF и ответы SDK моделируются: тесты проверяют очистку памяти, отмену поздних операций, обёртку только при актуальных ключах и отсутствие PRF в серверном payload. OAuth-проверки используют mock ответы провайдера и настоящие state, browser binding и PKCE.

## Обязательные проверки CI перед релизом

Результаты доступны в [GitHub Actions](https://github.com/trillvertual/custodian/actions). Публикация требует успешного выполнения:

- Typecheck, format check, полного unit/integration suite, `npm audit` и сборки.
- Объединённого Playwright suite из 28 desktop/mobile сценариев на финальном commit.
- Сборки Docker и запуска с PostgreSQL 18: healthcheck, API, миграции и rescue CLI.
- Сканирования финального публичного snapshot и source/runtime архивов, SBOM и release metadata до загрузки assets.
- Проверки контрольных сумм, наличия `LICENSE` в архивах и smoke test опубликованного контейнерного образа.

Исходники и release archives проверяются Gitleaks с закреплённой версией и SHA-256. Сканер не открывает локальный `.env`, не печатает найденные значения и отклоняет запрещённые пути в архивах. Область и воспроизводимые команды: [PUBLICATION-AUDIT.md](PUBLICATION-AUDIT.md).

## Что не проверено

Docker/PostgreSQL 18 не запускались локально; они проверяются отдельным CI job. Embedded PGlite не заменяет многопроцессную конкуренцию PostgreSQL или эксплуатационное восстановление из `pg_dump`.

Docker/PostgreSQL 18, миграции и container/rescue smoke прошли в [CI для кода 0.2.0](https://github.com/trillvertual/custodian/actions/runs/38440986320). Итоговый Release workflow повторяет эти проверки и проверяет опубликованный образ по точному digest.

Вход с реальными Telegram/GitHub аккаунтами, регистрация на физическом Passkey/PRF устройстве, физический мобильный браузер и assistive technologies не проверялись. Независимый аудит криптографии, pentest и production deployment не выполнялись. Автоматические проверки доступности не подтверждают полное соответствие WCAG.
