# Проверки Custodian 0.5.4

Дата: 14 ноября 2026 года. CI: Node.js 22.23.3, локальные проверки: 22.23.4. Для всех тестов используются изолированные базы и синтетические данные.

## Локальные проверки и CI

| Проверка                                   | Результат                                                                                  |
| ------------------------------------------ | ------------------------------------------------------------------------------------------ |
| `npm run typecheck`                        | Успешно: frontend, backend, core, rescue, scripts и тесты                                  |
| `npm test`                                 | 124 теста в 17 файлах прошли                                                               |
| `npm run build`                            | Успешно: frontend и оба Node.js entrypoint                                                 |
| `npm run release:check`                    | Версии и контракт релиза согласованы                                                       |
| `npm audit`                                | 0 известных уязвимостей в полном дереве                                                    |
| `npm run secrets:check` с build-каталогами | 0 находок в рабочих файлах, доступных Git refs и собранных web/server/rescue файлах        |
| Полный Playwright suite в Chromium         | 34 desktop/mobile сценария; 68 проверок axe в обеих темах без нарушений проверенных правил |

Для v0.4.0 добавлены реальные encrypted batch CRUD, конкурентные повторы и полный rollback при конфликте, личное шифрование черновиков, ревизии и конфликты вкладок, аварийный буфер и восстановление сразу после перезагрузки, PNG QR, вставка, синтетическая камера и остановка поздно разрешённого MediaStream. Потеря ответа после успешного сохранения повторяет тот же ciphertext и оставляет одну запись. Новые suite используют отдельные синтетические API, сохраняя production лимит входа.

Прежние сценарии проверяют быстрые действия и clipboard, горячие клавиши, сохранение только ID недавних записей, замену шаблона с подтверждением и создание отдельной зашифрованной записи без изменения оригинала. Unit-тесты проверяют очистку всех значений при копировании структуры, изоляцию истории по пользователям и отмену отложенного копирования после закрытия, блокировки, смены ключей или запроса.

Функциональные browser-сценарии проверяют зашифрованные CRUD/history/trash, clipboard, ручную блокировку, custom controls, клавиатуру, адаптивность и непрерывность диалогов. Финальные сценарии доступности также проверяют reduced motion, переполнение страницы и получение Brotli ресурсов.

React/Fastify/libsodium/PGlite тесты проверяют регистрацию владельца, обязательное сохранение rescue-ключа, Origin/CSRF, права owner/admin, одноразовые приглашения, optimistic concurrency, смену пароля без изменения ciphertext, отзыв и ротацию ключей. Rescue-проверки включают неверный ключ, rollback, восстановление владельца, отзыв прежних методов входа, права plaintext-файла 0600 и отказ перезаписывать существующий файл.

В unit/API сценариях WebAuthn assertion подписывается синтетическим P-256 ключом и проверяется настоящим SimpleWebAuthn verifier; отсутствие user verification отклоняется. В проверках PRF ответы SDK моделируются: тесты проверяют очистку памяти, отмену поздних операций, обёртку только при актуальных ключах и отсутствие PRF в серверном payload. OAuth-проверки используют mock ответы провайдера и настоящие state, browser binding и PKCE.

## Проверки 0.5.4

В общий release candidate включены пять PR Dependabot: PGlite 0.5.16, fake-indexeddb 6.2.8, jsdom 31.0.0, Radix Slot 1.5.0 и Tabler Icons React 3.51.0. Все комментарии What The Diff и результаты исходных PR разобраны; открытых inline-замечаний нет. Зелёный CI отдельных PR не заменяет проверку совместного дерева релиза. Локально полный набор из 124 тестов прошёл на объединённых зависимостях; production SBOM содержит 207 уникальных компонентов и 220 путей установки, включая workspace-пакеты. Проверены engines всех lockfile-пакетов на совместимость с Node 22.23.3.

jsdom 31 требует Node `^22.22.2 || ^24.15.0 || >=26`; используется закреплённый Node 22.23.3. Его DOM/CSS и XML-парсинг проверяются существующими unit/UI/import сценариями. Optional native canvas backend не установлен; QR/paste/camera проверяет настоящий Chromium. PGlite и fake-indexeddb остаются dev-инструментами, production PostgreSQL 18 не заменяется.

## Проверки 0.5.3

15 сценариев production SBOM проверяют сохранение совместных runtime/dev-пакетов, workspace-пути, объединение duplicate refs с hashes/лицензиями, исключение dev-only компонентов, полноту по lockfile, package identities и целостность/связность графа. Отдельный сценарий проверяет реальное установленное production-дерево. Экспорт содержит 207 уникальных компонентов и 219 путей установки, включая workspace-пакеты. Optional platform-пакеты могут отсутствовать. Отдельно проверены отсутствие прямых dev-связей от корня к Fastify/React при сохранении production-путей через workspace, сохранение поздних лицензий и отказ при противоречащих лицензиях.

Public-release verifier расширен до 19 сценариев: неполный SBOM и несовпадение source/runtime lockfiles отклоняются до записи скачанных файлов. Browser и Docker/PostgreSQL проверки повторяются в CI релизного PR; локальный browser-прогон для этой правки упаковщика не повторялся.

## Проверки 0.5.2

17 автоматических сценариев public-release verifier входят в обычный `npm test` до публикации. Они используют локальные архивы с настоящим Git-маркером и mock-сеть: позитивный релиз, неверные checksum/revision, устаревшие source/runtime той же версии, отсутствие revision metadata, OCI digest/labels/attestation, недопустимый URL, size и непустой destination. На ошибке скачанные данные не сохраняются. Упаковщик также проверяет реальные архивы до формирования релиза.

Полный релизный CI дополнительно включает типизированный ESLint, positive/negative lint smoke, Snyk и Trivy. React/renderer обновляются согласованно; установки с `--engine-strict` не принимают зависимости с неподдерживаемым Node. QR image/paste/camera, остановка позднего MediaStream и остальные desktop/mobile сценарии сохраняются. Виртуальная камера и WebAuthn не заменяют физические устройства.

Trivy публикует полный SARIF и блокирует исправимые HIGH/CRITICAL. Наличие upstream-находок без исправления не скрывается и не означает, что image полностью свободен от CVE. Область проверок и политика: [AUTOMATED-REVIEW.md](AUTOMATED-REVIEW.md).

## Доверенные браузеры

Добавлен серверный credential ID сессии и миграция 4. `tests/trusted-devices.test.ts` использует настоящие подписи P-256, production SimpleWebAuthn verifier, WebCrypto AES-GCM и IndexedDB. Проверяются неэкспортируемость ключа, отсутствие личного ключа/оболочки в browser storage, привязка всех AAD-полей, повреждение ciphertext, чужой администратор, старый или другой способ входа, другой credential, отзыв доверия, изменение identity, блокировка участника и удаление Passkey. Docker/PostgreSQL smoke дополнен подписанным non-PRF assertion, настройкой, повтором, расшифровкой, проверкой свежести и отзывом доверия.

Новые Chromium desktop/mobile сценарии используют CDP virtual authenticator без PRF и настоящий браузерный WebAuthn API с проверкой на сервере. Проверяются однократная настройка паролем, последующий вход и открытие после reload одним Passkey, настройка через настройки аккаунта, отзыв и потеря локального ключа. Виртуальный authenticator воспроизводит отсутствие PRF; реальный аккаунт Bitwarden и физические устройства в этих сценариях не используются.

Для WebAuthn выделены localhost API на портах 3014/3015; прежние четыре browser suite изолированы на 3010–3013. Новые окна проверяются axe в обеих темах. Полные результаты доступны в [CI финального кода](https://github.com/trillvertual/custodian/actions/runs/41231740420). Независимый криптографический аудит не выполнялся.

## Обязательные проверки CI перед релизом

Результаты доступны в [GitHub Actions](https://github.com/trillvertual/custodian/actions). Публикация требует успешного выполнения:

- Typecheck, format check, полного unit/integration suite, `npm audit` и сборки.
- Объединённого Playwright suite из 34 desktop/mobile сценариев на финальном commit.
- Сборки Docker и запуска с PostgreSQL 18: healthcheck, API, миграции и rescue CLI.
- Сканирования финального публичного snapshot и source/runtime архивов, SBOM и release metadata до загрузки assets.
- Проверки контрольных сумм, наличия `LICENSE` в архивах и smoke test опубликованного контейнерного образа.

Исходники и release archives проверяются Gitleaks с закреплённой версией и SHA-256. Сканер не открывает локальный `.env`, не печатает найденные значения и отклоняет запрещённые пути в архивах. Область и воспроизводимые команды: [PUBLICATION-AUDIT.md](PUBLICATION-AUDIT.md).

## Что не проверено

Docker/PostgreSQL 18 не запускались локально; они проверяются отдельным CI job. Embedded PGlite не заменяет многопроцессную конкуренцию PostgreSQL или эксплуатационное восстановление из `pg_dump`.

Docker/PostgreSQL 18, миграции и container/rescue smoke прошли в [CI кода обновления зависимостей](https://github.com/trillvertual/custodian/actions/runs/41231740420). Итоговый Release workflow повторяет эти проверки и проверяет опубликованный образ по точному digest.

Вход с реальными Telegram/GitHub аккаунтами, регистрация на физическом Passkey/PRF устройстве, физический мобильный браузер и assistive technologies не проверялись. Независимый аудит криптографии, pentest и production deployment не выполнялись. Автоматические проверки доступности не подтверждают полное соответствие WCAG.
