# Custodian и менеджеры паролей

## Какие поля можно заполнять

Bitwarden и браузерный менеджер паролей могут сохранять аккаунт Custodian и заполнять вход, разблокировку, регистрацию и смену пароля. У этих форм стабильные идентификаторы и имена полей, `autocomplete="username"`, `current-password` или `new-password`. Разблокировка, восстановление и смена пароля показывают логин текущего участника, чтобы пароль не связывался с произвольно выбранным аккаунтом.

Содержимое редактируемых записей, API-токены, SSH-ключи, TOTP, заметки и код первоначальной настройки не являются паролем от Custodian. Такие поля получают `autocomplete="off"` и `data-bwignore="true"`. Ссылка приглашения отображается как выделяемый текст, а не HTML input: её можно скопировать кнопкой или через Ctrl/⌘+A, Ctrl/⌘+C, когда ссылка в фокусе.

Это подсказки клиентам, не средство защиты от расширений. Расширение с доступом к странице может читать доступное содержимое и применять собственные эвристики. Нельзя гарантировать подавление всех уведомлений одной разметкой или изменить настройки чужого расширения со страницы.

## Bitwarden и разные поддомены

По умолчанию `Base domain` объединяет поддомены. Если на `service-a.example.test` и `service-b.example.test` разные аккаунты, выберите в Bitwarden **Settings → Autofill → Default URI match detection → Host**. `Host` сопоставляет имя хоста и указанный порт; путь страницы не разделяет аккаунты.

Проверьте также сохранённые записи: настройка конкретного Website URI имеет приоритет над общей. Для независимых сервисов установите **Host** у каждого адреса. Не заменяйте чужую запись при регистрации Custodian; при сохранении создайте отдельный логин с адресом своей установки.

В версиях расширения, где есть **Allow websites to exclude fields to autofill**, включите этот параметр и перезагрузите Custodian: он разрешает учитывать `data-bwignore`. Название и доступность зависят от версии. Страница не переключает его автоматически.

Если уведомления сохранения вообще не нужны на Custodian, Bitwarden позволяет добавить хост установки в **Settings → Notifications → Excluded domains**. Это также подавляет уведомления сохранения/использования Passkey; выбирайте исключение осознанно.

Официальные источники: [URI matching](https://bitwarden.com/help/uri-match-detection/), [исключения autosave](https://bitwarden.com/help/exclude-domains/), [реализация opt-in для data-bwignore](https://github.com/bitwarden/clients/blob/57e52fcc2fdfe4ed80df83a382f7d1e02958a850/apps/browser/src/autofill/services/collect-autofill-content.service.ts).

## Passkey из Bitwarden без повторного пароля

В v0.5.0 добавлена опция **«Доверять этому браузеру»**. При первом входе с Passkey, который не вернул PRF, введите пароль и включите эту опцию. Следующие входы с тем же Passkey в этом профиле браузера открывают записи сразу. Парольный вход остаётся резервным способом для другого браузера или очищенного профиля.

На уже открытом хранилище настройка доступна через **Настройки → Способы входа → Доверенные браузеры → Настроить**. Выберите Passkey, задайте понятное название и нажмите **«Запомнить этот браузер»**. Подтверждение Passkey обязательно. Там же можно отозвать доверие своему или другому браузеру.

Это отдельный способ открытия, а не добавление PRF в Bitwarden. В браузере хранится неэкспортируемый AES-256-GCM ключ WebCrypto. Сервер хранит зашифрованный им личный ключ и возвращает его только после свежего подтверждения нужного Passkey. Шифрование записей и PRF-вход продолжают работать как прежде. Подробности и ограничения: [SECURITY.md](SECURITY.md#доверенный-браузер-без-prf).

После очистки данных сайта, отзыва доверия, удаления Passkey или восстановления личного ключа потребуется настройка заново. На общем компьютере не включайте доверие браузеру. Отзыв запрещает будущую разблокировку; уже открытые и скопированные данные он не удаляет.

## Варианты обмена данными

- **Bitwarden → Custodian:** уже доступен локальный импорт JSON/CSV с предпросмотром и проверкой дублей. Ограничения перечислены в [DATA-TOOLS.md](DATA-TOOLS.md).
- **Custodian → Bitwarden:** возможное расширение – экспорт выбранных записей в совместимый JSON с явным подтверждением. В текущей версии такого экспорта нет.
- **Односторонняя синхронизация:** возможный отдельный локальный коннектор на базе `bw` CLI, с выбранной коллекцией, одним источником истины и подтверждением конфликтов. Ему потребуется доступ к расшифрованным данным на устройстве; сервер Custodian не должен получать мастер-пароль или сессию Bitwarden. Это предложение, не реализованная функция.

Public API Bitwarden предназначен для управления организацией; для записей используются CLI/Vault Management API. Двусторонняя синхронизация дополнительно требует устойчивых идентификаторов, сопоставления версий, конфликтов, удаления и отзыва доступа. Источники: [Password Manager APIs](https://bitwarden.com/help/bitwarden-apis/), [CLI](https://bitwarden.com/help/cli/).
