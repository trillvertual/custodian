# Автоматические проверки Custodian

| Инструмент    | Назначение                                                             | Подключение                                                           |
| ------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------- |
| ESLint        | Ошибки Promise, некорректный await, опасные конструкции, порядок Hooks | `npm run lint`, обязательный шаг существующего CI                     |
| Trivy         | Уязвимости системных и Node-пакетов внутри образа                      | CI, Release и ежедневный workflow Published image security            |
| Snyk          | Независимая база уязвимостей зависимостей приложения и линтера         | Workflow Snyk, repository secret `SNYK_TOKEN`                         |
| Greptile      | Ревью логики с контекстом прав, ключей, сессий и восстановления        | GitHub App + включение репозитория в Greptile; правила в `.greptile/` |
| What The Diff | Краткое описание изменений для ревью                                   | Авторизация сервиса + включение репозитория в его dashboard           |

Наличие конфигурации в Git не устанавливает внешние Apps. Для первых трёх инструментов результат подтверждается запусками CI. Для Greptile и What The Diff проверяйте реальный комментарий/ревью на PR после активации. Типы, тесты, Playwright, CodeQL, Gitleaks и `npm audit` сохраняются.

## ESLint

```bash
npm ci
npm run lint:install
npm run lint
npm run lint:verify
npm audit --prefix tools/lint --audit-level=high
```

Приложение использует TypeScript 7. Текущий typescript-eslint поддерживает TypeScript `<6.1`, поэтому инструменты линтера установлены отдельно в `tools/lint`: ESLint 10 и TypeScript 6.0.3. Это не меняет компилятор приложения, production-зависимости или runtime-архив. Оба lockfile коммитятся и проверяются; для tooling настроен отдельный Dependabot.

Начальный блокирующий профиль включает типизированные проверки Promise/await и `rules-of-hooks`. Стилистические правила и автоматическое исправление зависимостей Effects не включены: слепое добавление зависимостей может перезапускать операции с ключами и черновиками. JSX callbacks могут возвращать Promise; реальная обработка ошибок внутри действия по-прежнему обязательна. Исключение диагностик, способных удерживать секреты через `Error.cause`, объясняется непосредственно у границы импорта.

`lint:verify` на временных файлах проверяет, что ошибочные Promise/await/Hooks действительно отвергаются, корректная обработка проходит, а TypeScript приложения не подменён. В `tools/lint` ограниченно обновлён minimatch до исправленной ветки 11; удалить override можно после соответствующего обновления зависимостей ESLint/typescript-eslint и повторного smoke test.

В dev-toolchain AJV 6 использует `uri-js`, для которого нет исправленной версии. Только для этой зависимости задан npm alias на `fast-uri 3.1.9`: используемые AJV методы parse/serialize/resolve проверяются через относительные JSON Schema `$ref`, а Unicode-ввод – в отдельном процессе с таймаутом. Это удаляет уязвимый парсер вместо подавления Snyk-находки. [Advisory](https://security.snyk.io/vuln/SNYK-JS-URIJS-19963963).

## Trivy

Версия Trivy и SHA Action закреплены. В CI проверяется ID только что собранного контейнера, в Release – точный опубликованный digest. Ежедневно в 07:23 UTC проверяется digest из `release.json` последнего публичного релиза; плавающий image tag не используется.

Полный SARIF содержит все уровни, включая уязвимости без исправления. Публикация и CI блокируются на **HIGH/CRITICAL с доступным исправлением**. Находки без исправления остаются видимыми для оценки риска; для них не создаётся blanket ignore. Ошибка загрузки базы или сканера является ошибкой проверки. SARIF попадает в GitHub Code Scanning; fork PR сканируется, но не получает права загрузки отчёта в базовый репозиторий.

Runtime обновляет пакеты Debian при сборке и не содержит npm/npx/corepack: сервер и rescue запускаются через `node`. Сборочная стадия продолжает использовать npm. Операторские npm-команды выполняются из source/runtime-архива на хосте, команды в контейнере описаны в README. Старые опубликованные образы не изменяются; исправленный Dockerfile попадёт в образ при следующем релизе.

## Snyk

Токен хранится только в зашифрованных GitHub Actions и Dependabot secrets репозитория с именем `SNYK_TOKEN`. Обычные Actions secrets недоступны PR от Dependabot, поэтому для них нужен второй secret с тем же именем. При ротации обновляйте оба. Установщик CLI не получает токен; он передаётся только проверке. CLI и установочный Action закреплены по версии/SHA. Скан включает приложение, npm workspaces и отдельный lint lockfile, включая dev-зависимости. HIGH и CRITICAL приводят к ошибке. Первая проверка выявила Fastify до 5.12.8; приложение обновлено до исправленной ветки 5.12.8. Для jsdom обновлён Undici до 8.12.4, устраняющий дополнительные HIGH/CRITICAL-находки в dev-цепочке. Fastify явно объявлен также в root devDependencies, поскольку API-тесты импортируют его напрямую. Локальные ignore-policy из PR не принимаются.

Отсутствующий токен даёт явную ошибку, а не зелёную пустую проверку. Fork PR не получает credential и пропускает Snyk; остальные локальные проверки продолжают работать. `pull_request_target` и выполнение PR-кода с расширенными правами не используются. Snyk GitHub App не нужен для этой CLI-интеграции; его установка отдельно не требуется.

[Получение токена](https://docs.snyk.io/developer-tools/snyk-cli/authenticate-to-use-the-cli). Токен, попавший в чат, скриншот или Git, нужно перевыпустить и обновить secret. Значение не передаётся через аргументы команд или коммит.

## Greptile: активация владельцем

1. [Установите Greptile Apps](https://github.com/apps/greptile-apps/installations/new), выбрав **Only select repositories → trillvertual/custodian**. Приватный архив Custodian и другие проекты не выбирайте.
2. В [Greptile](https://app.greptile.com/) свяжите установку и включите только Custodian. Оставьте бесплатный Starter либо одобренный OSS-план; не включайте пополнение баланса без отдельного решения владельца.
3. Настройки `.greptile/config.json` включают ревью открытия и новых коммитов, базовый уровень усилий, содержательные замечания и отключают auto-approval. Summary и диаграммы выключены, чтобы не дублировать What The Diff.
4. На проверочном PR дождитесь Greptile review/status check. При необходимости вызовите `@greptileai` в комментарии.

Публично объявленные права Greptile Apps включают **contents:write и workflows:write**, а не только чтение; GitHub не позволяет уменьшить фиксированный набор прав App. Владелец должен видеть эти права при установке. Конфигурация отключает автоматическое одобрение, но не уменьшает права самого App. Существующая branch protection сохраняется; AI-оценка не заменяет review изменений шифрования, восстановления и доступов.

[Схема конфигурации](https://www.greptile.com/docs/code-review/greptile-config-reference), [тарифы и OSS](https://www.greptile.com/pricing).

## What The Diff: активация владельцем

1. [Войдите через GitHub](https://app.whatthediff.ai/), предоставив доступ только к Custodian через [What The Diff App](https://github.com/apps/what-the-diff/installations/new).
2. В dashboard вручную включите репозиторий. Сервис не активируется одним config-файлом; поддерживаемого YAML в репозитории нет.
3. Выберите **AI comments → PR creation**. Не включайте генерацию на каждый push: актуальные замечания даёт Greptile, а повторное описание расходует квоту. Draft/WIP и `dependabot/*` можно исключить из автоматических summary.
4. Исключите `**/node_modules/**`, `**/dist/**`, `**/package-lock.json`, `docs/screenshots/**`. Начните с лимита 15 000 токенов на PR и бесплатного плана без платного upgrade. Summary должен быть коротким и описывать результат изменения; не добавляйте joke/poem или рассылки.
5. На обычном PR проверьте комментарий от `what-the-diff`. Авторское описание и секции проверки/совместимости остаются на месте.

App объявляет чтение contents/email и запись issues/pull requests. Автоматический merge не включается.

[Поддерживаемые настройки](https://whatthediff.ai/getting-started).
